# 2026-10-14 工作记录

- 分析 resume-screening 项目现状与用户需求的差距：
  - 当前实现是「简历筛选」智能体（HR/招聘方视角），而非用户想要的「投递简历」智能体（求职者视角）。
  - 核心工作流：JD + 多份简历 → 解析 → 硬性过滤 → AI 评分 → 输出候选人评估报告。
  - 缺失：岗位发现、职位匹配、招聘平台投递、投递状态追踪等求职者侧能力。
- 可复用资产：LLM 调用封装（llm_client.py）、简历文件解析工具（parse_resume_file）、FastAPI + LangGraph 服务骨架（main.py）。

## 改造方案确定（用户确认）

- 视角：求职者「投递简历智能体」。
- 已确认两个关键决策：
  1. 自动化程度 = 人工在环（Agent 出匹配清单+定制招呼语，用户确认后投；不做浏览器自动点击，规避封号/合规风险）。
  2. 目标平台 = BOSS直聘优先（贴合用户现有每日投递习惯）。
- 新工作流：简历画像 → 岗位发现 → 岗位匹配(评分逻辑翻转) → 投递决策(生成招呼语) → [人工确认] 投递执行 → 状态追踪 → 报告。
- 四阶段：P1 匹配引擎(简历画像+匹配+排名报告) / P2 岗位发现(BOSS直聘) / P3 投递执行+状态追踪 / P4 每日汇报复盘。
